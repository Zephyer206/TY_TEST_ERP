# 视角切换安全质量检查清单

**目的**：验证超级管理员视角切换功能的权限隔离安全性需求质量
**创建日期**：2026-06-13
**功能**：[spec.md](../spec.md)

**关联用户故事**：US10 — 超级管理员视角切换（Priority: P3）
**关联需求**：FR-079 ~ FR-085
**关联任务**：T085-T090
**关联场景**：Quickstart Scenario 5

## 需求完整性

- [ ] FR-079 视角切换后隐藏 role_level >= 9 专用按钮的判断逻辑，是否在服务端和客户端双重校验？[完整性, Spec §FR-079]
- [ ] FR-080 权限验证拦截率 100%，是否有完整的权限矩阵覆盖所有 API 端点？[完整性, Spec §FR-080]
- [ ] FR-081 视角切换记录（切换时间/目标/原因）的存储表结构是否已定义？[完整性, Spec §FR-081]
- [ ] FR-082 Session Cookie 包含用户角色信息，每次请求验证角色有效性的技术方案是否有具体实现？[完整性, Spec §FR-082]
- [ ] FR-083 图纸文件路径统一函数是否已实现，禁止硬编码的代码规范是否有强制措施？[完整性, Spec §FR-083]
- [ ] FR-084 客户分配后图纸路径迁移的原子操作，回滚机制的技术实现是否有具体方案？[完整性, Spec §FR-084]
- [ ] FR-085 所有 DELETE 操作软删除（is_deleted 标记）的统一实现是否覆盖所有业务表？[完整性, Spec §FR-085]
- [ ] 视角切换时，当前用户的 API Token/Session 是否需要重新生成？[Gap]
- [ ] 超级管理员切换视角后，是否允许同时打开多个不同视角的会话？[Gap]
