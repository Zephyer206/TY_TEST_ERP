# 功能规格说明书：冲压工厂 ERP 系统

**功能分支**：`001-erp-system-architecture`

**创建日期**：2026-06-10

**状态**：起草中

**输入**：用户需求描述 — 建立围绕业务部和老板为核心的冲压工厂数字化管理系统

---

## 概述

Zephyr_test_ERP 是一套面向冲压制造企业的综合性企业资源管理系统，覆盖从报价接单、模具开发、原料采购、生产执行、质量管控到包装出货的完整业务闭环。

系统以**业务部**和**老板**为核心：业务部是整个系统的入口和出口（接单始于报价，终局是发货和回款），老板是最终决策者（掌控审批权力、掌握全局数据）。

其余部门（生产部、开发部、原料仓库、品管部、全检部、喷涂部）作为支撑链条环绕运转。

**核心价值主张**：

- 业务数字化：报价、订单、生产、出货全链路在线
- 审批可控：老板对每一笔报价拥有最终审批权
- 数据贯通：从报价到出货的数据无缝流转，消除信息孤岛
- 权限分明：各司其职，超级管理员可切换部门视角全局把控

## 用户与角色

系统涉及以下角色，每个角色有明确的职责边界：

| 角色 | 所属部门 | 核心职责 |
|------|---------|---------|
| 老板（role_level=9） | 老板 | 最终审批、全局数据查看 |
| 业务经理（role_level=5） | 业务部 | 报价、报价审批提交、客户管理 |
| 设计工程师（role_level=4） | 开发部-设计组 | T/W/P 参数填写、报价参数配置 |
| 模具工程师（role_level=2） | 开发部-模具组 | 模具台账管理、模具维修、技术审核 |
| 组长/主管（role_level=3） | 生产部 | 生产计划、工单管理、机台调度 |
| 操作工（role_level=1） | 生产部 | 车间报工（冲次/简易） |
| 包装组长（role_level=3） | 全检部 | 包装、发货、库存管理 |
| 仓库主管（role_level=3） | 原料仓库 | 原材料管理、批次追踪、IQC |
| 质检主管（role_level=3） | 品管部 | 巡检、OQC、首件放行 |
| 喷涂工程师（role_level=4） | 喷涂部 | 喷涂配方管理、喷涂报工 |
| 超级管理员（role_level>=10） | admin | 视角切换、系统配置 |

**部门依赖关系**：老板（审批决策）→ 业务部（接单、报价、发货）↔ 原料仓库（供料）→ 开发部（模具、T/W/P 参数）↔ 品管部（首件/巡检/OQC）→ 生产部（机台、报工）↔ 全检部（包装、入库）→ 喷涂部（表面处理）

## 用户场景与测试

> **重要说明**：用户故事按重要性排序为独立可测试的_slice_。实现任意一个故事都应交付一个可用的 MVP。

### 用户故事 1 — 报价与审批（Priority: P1）

业务经理对陌生客户的新询价，能够快速发起报价、直接填写价格和技术参数、提交老板审批，全程可追溯。报价单老板审批通过后，分两条路径：直接进入量产，或先经过样件阶段、样件通过之后再量产。

**零件状态说明**：零件（parts）状态流转为：草稿（Draft）→ 样件（Sampling）→ 量产（MassProduction）→ 淘汰（Obsolete）。定点路径"直接量产"跳过硬样件阶段；定点路径"先做样件"需经样件评审通过后才能切换为量产状态。

**优先级理由**：报价是从订单到交付的起点，没有报价就没有后续一切，是系统最核心的业务入口。

**独立测试**：可通过创建报价单 → 填写价格和技术参数（可跳过技术审核）→ 老板审批 → 定点确认（选量产/样件路径）的完整链路独立验证。

**验收场景**：

1. **Given** 业务经理已登录，**When** 新建报价单并填写零件、客户、年用量信息，**Then** 报价单进入"等待技术审核"状态（或直接进入草稿状态，由业务经理自行决定是否先提交技术审核）
2. **Given** 报价单等待技术审核，**When** 设计工程师填写 T/W/P、模具费、穴数、吨位并提交，**Then** 报价单进入"技术审核通过"或"技术驳回"状态；驳回后业务经理可修改参数重新提交，无需从头走完整审批流
3. **Given** 报价单等待技术审核或技术审核通过，**When** 业务经理直接填写冲压费、表面处理、利润，**Then** 报价单进入"草稿"状态，业务经理可随时修改价格后再提交老板审批
4. **Given** 报价单处于草稿，**When** 业务经理提交老板审批，**Then** 报价单进入"待老板审批"状态
5. **Given** 报价单待老板审批，**When** 老板审批通过，**Then** 报价单锁定价格快照，进入"已审批"状态，业务经理可进行定点确认
6. **Given** 报价单待老板审批，**When** 老板审批驳回，**Then** 报价单退回"草稿"状态并记录驳回原因，业务经理修改后可重新提交，无需再次经过技术审核
7. **Given** 报价单已审批，**When** 业务经理根据客户要求选择直接量产或先做样件并确认定点，**Then** 系统按所选路径推进：直接量产 → 零件进入生产就绪状态；先做样件 → 零件进入样件阶段
8. **Given** 报价单已审批且零件处于样件阶段，**When** 样件评审通过，**Then** 零件从样件阶段切换为生产就绪状态，系统自动更新零件表与模具台账
9. **Given** 定点确认完成，**When** 系统执行定点写入，**Then** 零件表的模具基础信息（模具编号、类型、吨位、PPAP 编号、客户件号、车型）和价格快照同步更新

### 用户故事 2 — 打样管理（Priority: P1）

组长或业务经理能够为定点确认后选择"先做样件"的零件创建打样任务，由老板审核确认后启动打样，执行客户评审，评审通过后将零件切换为量产状态；业务经理可对待处理打样任务进行加急处理。

**优先级理由**：打样是新零件量产前的验证关卡，直接影响客户定点信心；老板审核确保打样资源投入经过确认；加急处理支持业务灵活应对客户紧急需求。

**独立测试**：可通过创建打样任务 → 老板审核 → 执行打样 → 客户评审通过 → 零件进入量产状态的流程独立验证。

**验收场景**：

1. **Given** 报价单已审批且业务经理选择了"先做样件"定点路径，**When** 组长或业务经理创建打样任务（关联零件、客户、下单时间、计划完成时间、样件数量），**Then** 打样任务进入"待审核"状态，等待老板确认
2. **Given** 打样任务待审核，**When** 老板审核并确认启动打样，**Then** 打样任务进入"待生产"状态，零件状态为"样件"（Sampling）
3. **Given** 打样任务待生产，**When** 组长安排打样生产并分配机台，**Then** 打样任务状态变为"打样中"，系统记录开始时间
4. **Given** 打样任务打样中，**When** 打样完成并提交样件，**Then** 打样任务进入"待评审"状态，系统记录实际完成时间，通知评审人（业务/品质/开发代为传达客户意见）
5. **Given** 打样任务待评审，**When** 评审人提交评审结果，**Then** 评审通过 → 打样任务状态变为"已通过"，零件状态从 Sampling 切换为 MassProduction；评审不通过 → 状态变为"未通过"，零件保持 Sampling 状态，可重新安排打样
6. **Given** 打样任务处于任意状态，**When** 业务经理或组长取消打样任务，**Then** 打样任务状态变为"已取消"，零件保持 Sampling 状态，可选择改为直接量产路径
7. **Given** 待处理打样任务（任意状态），**When** 业务经理手动标记加急，**Then** 打样任务加急标记激活，系统在列表中优先展示，并可通知相关人员

**打样时间字段说明**：每个打样任务必须记录下单时间、计划完成时间、实际完成时间三个节点，系统自动计算计划偏差天数用于考核。

### 用户故事 3 — 模具管理与维修（Priority: P1）

模具工程师能够管理模具台账，对故障机台执行两扫制维修流程，确保生产中断时间最短。

**优先级理由**：模具是冲压生产的核心工具，维修效率直接影响机台利用率和订单交付。

**独立测试**：可通过新建模具档案 → 机台报障 → 维修完成 → 恢复生产的流程独立验证。

**验收场景**：

1. **Given** 模具工程师已登录，**When** 新建模具档案（编号、客户产品号、穴数、吨位、PPAP 编号、车型），**Then** 模具台账新增一条记录，状态为"可用"
2. **Given** 机台处于运行中，**When** 操作工或组长上报故障，**Then** 机台进入"待确认"状态，系统通知模具工程师
3. **Given** 机台待确认，**When** 模具工程师确认故障并发起维修，**Then** 机台进入"维修中"状态
4. **Given** 机台维修中，**When** 维修完成并选择在线修复，**Then** 机台恢复为"运行"状态
5. **Given** 机台维修中，**When** 维修完成需要拆模下线，**Then** 机台进入"停机"状态，进入待修池等待再次分配

---

### 用户故事 4 — 生产计划与报工（Priority: P1）

组长能够创建生产计划并分配机台，操作工能够通过车间终端扫码报工，实时更新产出数据。

**优先级理由**：生产是工厂价值交付的核心环节，报工数据是产值统计和质量追踪的基础。

**独立测试**：可通过创建生产计划 → 分配机台 → 开启报工会话 → 结账并产出的流程独立验证。

**验收场景**：

1. **Given** 组长已登录，**When** 创建生产计划（关联零件、总数量、截止日期、紧急程度），**Then** 计划进入"已计划"状态
2. **Given** 生产计划已计划，**When** 组长分配机台并上线排产，**Then** 机台状态变为"运行"，计划状态变为"进行中"
3. **Given** 机台运行中，**When** 操作工扫码进入车间终端并开启报工会话，**Then** 报工会话开启，系统记录开始时间
4. **Given** 报工会话开启中，**When** 操作工提交冲次报工（冲次 × 穴数），**Then** 系统计算产出数量，记录良品/不良品数
5. **Given** 报工会话开启中，**When** 操作工结账会话，**Then** 会话关闭，产出汇总写入报工记录，计划完成量更新

---

### 用户故事 5 — 质量管控与放行（Priority: P2）

质检主管能够执行首件检验和 OQC 出货检验，紧急情况下高权限用户可发起强行特赦，所有放行操作留有审计轨迹。

**优先级理由**：质量是客户信任的底线，首件确认和出货检验是防止批量质量事故的关键卡点。

**独立测试**：可通过首件检验通过 → 批量生产 → OQC 出货检验 → 发货的流程独立验证。

**验收场景**：

1. **Given** 批量生产启动前，**When** 质检主管对首件进行检验并批准放行，**Then** 首件放行记录生成，系统允许批量生产
2. **Given** 批量生产完成，**When** 质检主管执行 OQC 出货检验（抽检数量、合格数量），**Then** OQC 报告生成，标记出货检验结果
3. **Given** OQC 检验失败，**When** 高权限用户（role_level >= 6）发起强行特赦并填写原因，**Then** 紧急放行记录生成，进入 QA 审计日志
4. **Given** 任意放行操作执行，**When** 系统记录操作，**Then** QA 审计日志包含操作人、时间、原因（正常放行或特赦）、零件标识

### 用户故事 6 — 原材料与批次管理（Priority: P2）

仓库主管能够管理原材料台账，对来料执行 IQC 检验，通过 QR 码追踪批次状态变化，支持分条操作。

**优先级理由**：原材料是生产的前置保障，批次追踪是质量追溯和成本核算的基础。

**独立测试**：可通过新建原材料 → 来料 IQC 检验 → 批次分配 → 分条操作的流程独立验证。

**验收场景**：

1. **Given** 仓库主管已登录，**When** 新增原材料台账（牌号、类型、供应商、当前重量），**Then** 原材料记录创建，批次初始状态为"可用"
2. **Given** 来料入库，**When** 仓库主管执行 IQC 检验（合格/不合格），**Then** 批次状态更新，合格批次可投入生产，不合格批次标记待处理
3. **Given** 批次在使用中，**When** 需要分条操作，**Then** 系统记录分条后宽度和重量变化，原始批次关联新的子批次
4. **Given** 材料消耗殆尽，**When** 批次重量归零或人工标记报废，**Then** 批次状态变为"已耗尽"或"已报废"，报废日志记录原因

---

### 用户故事 7 — 包装发货全链路（Priority: P2）

包装组长能够管理包装扫码、全检入库、发货单全流程，确保发货零件与客户件号准确匹配。

**优先级理由**：发货是订单交付的最后一步，包装扫码和发货单匹配错误将导致客户投诉。

**独立测试**：可通过包装扫码 → 全检入库 → 创建发货单 → 确认发货的流程独立验证。

**验收场景**：

1. **Given** 零件完成生产，**When** 包装组长扫描零件并录入包装数量，**Then** 包装记录生成，零件进入待检库存（WIP）
2. **Given** 零件在 WIP 中，**When** 全检完成并合格，**Then** 零件正品库存增加，不良品记录进入缺陷日志
3. **Given** 需要发货，**When** 创建发货单并添加明细（通过客户件号别名匹配零件），**Then** 发货单进入"待发货"状态
4. **Given** 发货单待发货，**When** 包装组长确认发货，**Then** 发货单状态变为"已发货"，系统更新库存和客户件号映射

---


喷涂工程师能够管理喷涂配方，通过扫码执行喷涂报工，记录各零件喷涂进度和物料余额。

**优先级理由**：喷涂是表面处理的关键工序，影响产品外观和耐腐蚀性，属于增值环节但非所有零件必经。

**独立测试**：可通过配置喷涂配方 → 扫码喷涂 → 记录产出的流程独立验证。

**验收场景**：

1. **Given** 喷涂工程师已登录，**When** 为零件配置喷涂配方（砂料、涂料、表面类型），**Then** 配方记录关联零件
2. **Given** 零件进入喷涂工序，**When** 操作工扫码并录入喷涂数量，**Then** 喷涂记录生成，零件喷涂进度更新
3. **Given** 喷涂完成，**When** 记录喷涂产出，**Then** 喷涂报工记录写入，物料余额扣减

**独立测试**：可通过配置喷涂配方 → 扫码喷涂 → 记录产出的流程独立验证。

1. **Given** 喷涂工程师已登录，**When** 为零件配置喷涂配方（砂料、涂料、表面类型），**Then** 配方记录关联零件
2. **Given** 零件进入喷涂工序，**When** 操作工扫码并录入喷涂数量，**Then** 喷涂记录生成，零件喷涂进度更新
3. **Given** 喷涂完成，**When** 记录喷涂产出，**Then** 喷涂报工记录写入，物料余额扣减

### 用户故事 9 — 价格台账与年降（Priority: P3）

业务经理和老板能够管理每个「零件+客户」的价格档案，按年录入单价和年销量，系统自动追踪年降。

**优先级理由**：价格台账是成本分析和年降追踪的数据基础，支持老板掌握每个订单的真实利润空间。

**独立测试**：可通过新建价格档案 → 录入年份单价 → 系统计算当前价格的流程独立验证。

**验收场景**：

1. **Given** 定点确认后，**When** 为零件+客户组合建立价格档案（材质、净重、毛重、材料单价、废料价），**Then** 价格档案创建，年份单价初始为空
2. **Given** 价格档案已建立，**When** 录入某年份的单价和年销量，**Then** 年份价格记录创建，当前价格自动取最新录入年份
3. **Given** 当前年份无录入，**When** 系统计算当前价格，**Then** 按年降规则逐年推算：price = base_price × (1 - reduction_pct)^elapsed_years
4. **Given** 需要调整价格，**When** 手动录入调价记录（新价、旧价、调价原因），**Then** 调价历史保留，系统使用最新价格

### 用户故事 10 — 超级管理员视角切换（Priority: P3）

超级管理员能够临时切换到任意部门视角查看系统全局，切换后无老板专用按钮泄露，防止越权自审。

**优先级理由**：超级管理员需要跨部门排查问题，但切换视角时必须严格隔离权限，防止 admin 角色借用老板权限自审报价。

**独立测试**：可通过超级管理员切换到业务视角 → 验证无老板审批按钮 → 切换回 admin → 验证恢复的流程独立验证。

**验收场景**：

1. **Given** 超级管理员已登录，**When** 切换到业务视角，**Then** 界面展示业务经理视图，隐藏所有 role_level >= 9 专用按钮
2. **Given** 超级管理员在业务视角，**When** 尝试访问老板审批页面，**Then** 系统拒绝访问，返回权限不足提示
3. **Given** 超级管理员在业务视角，**When** 切换回 admin 视角，**Then** 所有权限恢复，系统正常展示所有管理功能

---

### 边界情况

- 报价单在技术审核阶段被驳回：业务经理收到驳回通知，可修改后重新提交，无需重新走一遍完整审批流
- 报价单老板审批驳回：退回草稿状态并记录驳回原因，业务经理修改后可重新提交，无需再次经过技术审核
- 定点确认时客户选择样件路径：零件进入样件阶段（Sampling），打样任务进入"待审核"状态，等待老板确认；老板驳回后打样任务可修改后重新提交
- 业务经理加急打样任务后：加急任务在打样清单中优先展示，系统可通知生产人员优先安排
- 机台故障时生产计划已排产：系统通知组长，组长可重新分配机台或调整计划截止日期
- 报工会话开启后操作工中断：会话保持开启状态，组长可代为结账，记录中断原因
- IQC 检验不合格的批次：自动冻结，通知仓库主管，需确认处理方式（退货/降级使用）后才能解冻
- 发货单取消：库存回退至全检入库状态，已打印的物流单据需手动处理
- 定点确认后发现报价参数错误：需由更高权限用户（老板）撤销定点，才能重新编辑
- 超级管理员切换视角期间有操作超时：自动恢复 admin 视角，强制刷新权限

## 功能需求

### 报价与审批（FR-001 ~ FR-017）

- **FR-001**：系统必须支持业务经理创建报价单，关联零件号并填写客户信息（客户产品号、车型）
- **FR-002**：系统必须支持填写预估年用量和年均用量
- **FR-003**：报价单状态流转规则：等待技术审核 → 技术通过/驳回 ↔ 草稿 → 待老板审批 → 已审批/驳回；技术审核不做强制等待，业务经理可跳过技术审核直接进入草稿状态填写价格
- **FR-004**：技术审核（role_level >= 4）必须填写 T（厚度）、W（宽度）、P（冲次）、穴数、吨位
- **FR-005**：技术审核必须配置模具费（金额）和模具费收取模式（直接收取/分摊计入单价）
- **FR-006**：业务经理必须能上传零件图纸，图纸按客户名+零件名+零件号分类存储
- **FR-007**：无客户时图纸暂存于临时路径，客户分配后自动迁移到标准路径
- **FR-008**：老板审批通过后系统必须锁定价格快照（包含材料单价、表面处理费、冲压费、模具费、利润）
- **FR-009**：老板审批驳回后报价单退回草稿状态并记录驳回原因，业务经理修改后可重新提交，无需再次经过技术审核
- **FR-010**：技术审核驳回后报价单退回等待技术审核状态，业务经理可修改参数重新提交，无需从头走完整审批流
- **FR-011**：报价单老板审批通过后，系统必须支持两条定点路径：直接进入量产，或先进入样件阶段、样件评审通过后再进入量产
- **FR-012**：定点确认时系统必须同步更新零件表的模具基础信息（模具编号、类型、吨位、PPAP 编号）和价格快照
- **FR-013**：系统必须支持多道表面处理计价，每道处理记录名称和费用
- **FR-014**：报价单状态变更必须记录操作人、操作时间、变更原因（驳回时）
- **FR-015**：业务经理（role_level >= 5）才能提交老板审批，普通业务（role_level=4）只能提交技术审核
- **FR-016**：报价单必须支持客户件号别名管理，同一零件对不同客户可有不同件号
- **FR-017**：图纸上传前系统必须生成唯一文件名，避免覆盖已有文件；模具费折扣率（0.0~1.0）在技术参数填写阶段设置

### 打样管理（FR-018 ~ FR-025）

- **FR-018**：报价单定点确认时选择"先做样件"路径后，系统必须自动创建打样任务并关联零件，任务初始状态为"待审核"
- **FR-019**：打样任务必须由老板（role_level >= 9）审核确认后才能进入生产阶段；老板审核时能看到打样任务的所有信息（零件、客户、下单时间、计划完成时间、样件数量）
- **FR-020**：打样任务必须包含：关联零件、下单时间、计划完成时间、实际完成时间、开始时间、样件数量、任务状态（待审核/待生产/打样中/待评审/已通过/未通过/已取消）、加急标记
- **FR-021**：打样任务只需记录开始时间和实际完成时间，不强制要求打样过程中的进度节点
- **FR-022**：打样任务提交评审后系统必须通知评审人（业务/品质/开发人员代为传达客户评审意见），评审人可填写评审意见后通过或不通过
- **FR-023**：打样评审通过后系统必须自动将零件状态从 Sampling 切换为 MassProduction，并同步更新零件表模具信息
- **FR-024**：打样评审不通过后零件保持 Sampling 状态，可修改参数后再次提交打样，无需重新创建报价单
- **FR-025**：业务经理可对待处理打样任务（任意状态）标记加急；加急任务在列表中优先展示，系统可通知相关人员

### 模具管理（FR-026 ~ FR-035）

- **FR-026**：系统必须支持模具工程师（role_level >= 2）管理模具台账
- **FR-027**：模具档案必须包含：模具编号、客户产品号、穴数、吨位、PPAP 编号、车型、模具状态
- **FR-028**：模具状态必须支持：可用（AVAILABLE）、使用中（IN_USE）、维修中（MAINTENANCE）、已改造（CONVERTED）、已报废（SCRAPPED）
- **FR-029**：机台故障时系统必须通知模具工程师，支持在线修复和拆模下线两种维修路径
- **FR-030**：维修完成后系统必须更新机台状态（在线修复→运行，拆模下线→停机）
- **FR-031**：待修池必须展示所有 pending_check 和 repairing 状态的机台模具及其故障原因
- **FR-032**：模具-零件关联必须支持从机台模具（die_parts）和模具台账（tooling_parts）两个维度查询
- **FR-033**：模具维修日志必须记录故障时间、故障原因、维修方案、维修完成时间
- **FR-034**：技术审核时必须上传 SDR 图纸，技术分析图纸与业务图纸分开存储
- **FR-035**：模具编号在定点确认前系统不得自动分配，报价阶段保持为空

### 生产计划与报工（FR-036 ~ FR-045）

- **FR-036**：组长（role_level >= 3）必须能够创建生产计划，关联零件、总数量、截止日期、紧急程度
- **FR-037**：生产计划状态必须支持：已计划（planned）、进行中（in_progress）、已完成（completed）、已取消（cancelled）、已关闭（closed）
- **FR-038**：机台上线排产后系统必须将机台状态更新为"运行"（running）
- **FR-039**：操作工（role_level >= 1）必须能够通过车间扫码入口进入报工界面
- **FR-040**：连续模（会话模式）必须支持：开启会话 → 多次冲次报工（冲次 × 穴数 = 产出）→ 结账会话
- **FR-041**：简易模必须支持直接报工，无需开启会话
- **FR-042**：报工记录必须包含：产出数量、良品数、不良品数、工时、报工时间
- **FR-043**：生产计划完成后系统必须更新完成数量和状态，支持组长强制完工或取消计划
- **FR-044**：机台状态必须支持 6 态：空闲（idle）、运行（running）、故障（fault）、待修（pending_check）、维修中（repairing）、停机（offline）
- **FR-045**：生产计划未完成时组长应能够重新分配机台，系统记录变更日志

### 质量管控（FR-046 ~ FR-051）

- **FR-046**：首件检验必须由质检主管（role_level >= 3）执行，需组长审批放行后才能开始批量生产
- **FR-047**：强行特赦（紧急放行）必须要求 role_level >= 6，并强制填写放行原因
- **FR-048**：所有放行操作（正常放行和强行特赦）必须写入 QA 审计日志，不可删除或覆盖
- **FR-049**：OQC 出货检验必须记录抽检数量（qty_inspected）和合格数量（qty_passed）
- **FR-050**：巡检日志必须记录巡检时间、巡检人、巡检零件、机台状态、异常描述
- **FR-051**：QA 审计日志必须包含：操作人、角色、操作时间、放行类型（正常/特赦）、零件标识、原因

### 原材料与仓库（FR-052 ~ FR-059）

- **FR-052**：原材料台账必须包含：材料牌号、类型、供应商、当前重量、状态
- **FR-053**：批次状态必须支持：可用（AVAILABLE）、使用中（IN_USE）、已消耗（CONSUMED）、已耗尽（DEPLETED）、已报废（SCRAPPED）
- **FR-054**：批次必须通过 QR 码追踪，扫码后展示批次的所有流转记录
- **FR-055**：IQC 检验状态必须支持：待检（pending）、合格（qualified）、不合格（unqualified）
- **FR-056**：IQC 不合格批次必须自动冻结，通知仓库主管确认处理方式后才能解冻
- **FR-057**：分条操作必须记录原始宽度/重量与分条后宽度/重量的变化，原始批次关联新子批次
- **FR-058**：仓库确认（is_whse_confirmed）标记必须控制批次是否可投入生产
- **FR-059**：材料报废日志必须记录报废原因（超期/损坏/超用）和操作人

### 包装与发货（FR-060 ~ FR-066）

- **FR-059**：包装扫码必须支持扫描零件、录入包装数量，自动关联当前工单
- **FR-060**：全检合格后正品库存必须增加（parts.stock_pcs），不良品进入 defect_logs 追踪
- **FR-061**：待检库存（WIP）必须独立展示全检前的在制品，允许查看包装扫码记录
- **FR-062**：发货单必须支持创建、添加明细、取消、确认发货全生命周期管理
- **FR-063**：发货明细匹配必须通过 delivery_note_items 和 customer_aliases 双重匹配零件
- **FR-064**：发货单取消时系统必须回退库存至全检入库状态
- **FR-065**：包装组长（role_level >= 3）才能执行发货确认操作

### 喷涂（FR-067 ~ FR-071）

- **FR-066**：喷涂配方必须包含：砂料（sand_material）、涂料（coating_material）、表面类型（surface_type）
- **FR-067**：喷涂扫码必须关联零件和当前工单，记录喷涂数量和配方版本
- **FR-068**：喷涂看板必须展示各零件的喷涂进度（已完成/待喷涂/喷涂中）

- **FR-070**：喷涂报工记录必须包含：零件标识、喷涂数量、良品数、不良品数、操作人、时间

### 价格台账（FR-072 ~ FR-077）

- **FR-071**：价格档案必须按「零件+客户」唯一约束，确保一个组合只有一个活跃档案
- **FR-072**：毛重计算公式必须为：毛重 = (T × W × P × 密度 × 穴数) / 1_000_000
- **FR-073**：材料成本计算必须为：材料成本 = 净重/1000 × 材料单价 - 废料量/1000 × 废料价
- **FR-074**：年份单价录入后系统必须自动取最新录入年份作为当前价格（若该年份 >= 当前年份）
- **FR-075**：若当前年份无录入，系统必须按年降规则逐年推算：price = base_price × (1 - reduction_pct)^elapsed_years
- **FR-076**：手动调价记录必须保留旧价、新价、调价原因和操作人，支持历史查询

### 权限与安全（FR-078 ~ FR-084）

- **FR-077**：超级管理员（role_level >= 10）切换部门视角后，系统必须隐藏所有 role_level >= 9 专用按钮
- **FR-078**：权限验证通过率必须达到 100%，任何越权访问必须被系统拦截并记录日志
- **FR-079**：超级管理员视角切换必须记录切换时间、切换目标、切换原因
- **FR-080**：Session Cookie 必须包含用户角色信息，每次请求验证角色有效性
- **FR-081**：图纸文件路径必须通过统一函数生成，禁止硬编码，防止路径遍历漏洞
- **FR-082**：客户分配后图纸从临时路径迁移必须原子操作，迁移失败时回滚原路径
- **FR-083**：所有 DELETE 操作必须软删除（is_deleted 标记），禁止物理删除业务数据

## 假设条件

- **目标用户具备基础数字素养**：操作工可通过扫码终端完成报工，无需复杂培训
- **工厂有稳定的网络环境**：车间终端与服务器之间延迟 < 500ms
- **每个零件对每个客户有唯一零件号**：customer_aliases 组合（part_id, customer_name, customer_part_no）不重复
- **模具编号在定点确认时由人工分配**：系统不自动生成模具编号，避免与工厂现有编号体系冲突
- **年降规则由业务经理年度维护**：系统仅计算和记录，不主动提醒
- **客户图纸由业务部上传，技术分析图纸由开发部上传**：两者的上传入口和存储路径分离
- **冲压机的穴数在模具制作后固定**：报工计算（冲次 × 穴数）中穴数取自模具台账而非报价单
- **喷涂为可选工序**：不是所有零件必经，系统支持跳过喷涂直接进入全检
- **定点路径由业务经理在定点确认时选择**：量产路径跳过硬样件阶段，样件路径需经样件评审通过后才能切换为量产状态；样件评审通过由谁批准[NEEDS CLARIFICATION: 样件评审通过需要什么权限的人批准？]
