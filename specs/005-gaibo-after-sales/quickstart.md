# gaibo 售后模块实施与验收快速指南

图纸 PDF 当前只预留详情位置和元数据接口，不启用上传；后续服务器本地存储、备份和迁移 COS 规划见 [pdf-storage-plan.md](pdf-storage-plan.md)。

## 1. 准备

1. 确认后端使用项目现有 Python 运行时和 PostgreSQL 配置；不要删除 `backend/.runtime312`。
2. 备份当前数据库，并记录 Alembic 当前 revision。
3. 确认工作区内旧安装包表和 FMG Excel 导入数据的行数。
4. 启动后端和前端，确认 `/health`、登录和现有零件页面仍可用。

## 2. 数据库迁移顺序

1. 创建 `gaibo_*` 新表、索引、外键和检查约束。
2. 创建 FMG 墨西哥工作区，并把旧安装包逐行导入安装包主表。
3. 将旧组件按顺序导入安装包组成；可确认的一一对应项关联单件，不能确认的保存为 `unlinked`，不得猜测。
4. 将 `drawing_status`、`sample_status`、`ppap_status` 解析为资料状态；原始文本和日期写入 `source_data`/备注。
5. 导入旧 change log 到统一历史表，记录迁移来源。
6. 生成对照报告：旧表/新表行数、核心字段非空率、组成数量、资料状态数量、价格数量和异常清单。
7. 对照报告通过后再启用新 API；观察期内旧表只读保留，不删除。

## 3. 后端验证

```powershell
alembic upgrade head
python -m compileall backend/app
pytest backend/tests -q
```

必须额外验证：

- 四个固定字段为空时 POST/PATCH 返回 400，数据库无半条记录。
- 同一单件关联客户 A/B 后，两个需求的价格、图纸和工艺互不覆盖。
- 同一需求切换当前工艺时只有一个 `is_current=true`。
- 安装包可同时包含已关联单件和 `unlinked` 暂存组成。
- 停用客户后历史记录仍可查询，默认列表不再展示停用客户。
- 全局搜索按客户件号、IBI、内部组成跨客户返回，并标明记录类型。

## 4. 前端验收

在真实运行的本地浏览器中完成以下路径：

1. 打开“售后”，看到“售后查询”、FMG 墨西哥及其他客户入口；客户入口使用同一页面结构。
2. 在“售后查询”搜索一个只存在于客户 B 的 IBI，结果显示客户、单件/安装包类型和核心字段。
3. 进入客户页，切换“单件/安装包”筛选，确认分页和状态筛选准确。
4. 打开同一单件在客户 A/B 下的详情，确认图纸、工艺和备注隔离。
5. 编辑价格或工艺并保存，确认列表立即更新且详情显示修改历史；取消编辑不得产生历史。
6. 打开安装包，确认组成顺序、数量、未关联状态和组成详情入口正常。
7. 验证桌面宽屏不出现无意义横向滚动；窄屏仍可访问搜索、筛选和详情。

## 5. 迁移验收门槛

- 核心字段、组成、资料状态、价格、备注和历史完整率为 100%。
- 无法从 Excel 明确映射的记录必须进入人工复核清单，不能静默导入或猜测。
- 全局搜索 P95 小于 2 秒；客户列表和详情在目标数据量下无明显等待。
- 新 API 和前端验收通过后，才允许制定旧表下线任务；本计划不直接删除旧表。
