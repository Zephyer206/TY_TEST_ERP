**日期**：2026-10-29（Asia/Hong_Kong）  
**工作分支**：本轮在现有 `main` 工作区编写规划；未创建实施分支。  
**依据**：[业务规格](spec.md)、本轮京西重工表格分析、现有代码及数据库只读核对。  
**状态（2026-10-30）**：A/B 简易核算代码已实施，验收结果与已知限制见 [acceptance.md](acceptance.md)。本轮成本核算范围为 A＋B 简易核算；C/F 详细分析及实绩联动仅保留后续规划，需求待完善。D/E 为独立价格业务扩展，不自动纳入本次首版。业务建议不视为用户已经确认。

## Summary：目标与用户流程

价格中心以现有零件为基础建立核算记录：选择客户和客户件号，关联到具体零件、模具及用料方案，带出已有资料，只补缺项，计算并保存当次依据。当前交付简易成本核算，用于京西重工任务；详细成本分析已有部分讨论但未完成，继续保留研究，不扩入本轮开发。

简易核算分别展示材料、表面处理、特殊成本、模摊，后两项独立选用、均非必选。特殊成本逐项记录名称、原因、金额及依据，模摊独立记录来源与金额/分摊依据，同一费用不重复计入。不用特殊成本默认装入人工、折旧、电费等详细分析项目；未选特殊成本或模摊不影响简易完成。

### 报价与核算的共用价格及收费规则

报价和核算使用同一套材料价格、废料价格、表面处理费率及计费规则，复用取数与后端 Decimal 计算服务，避免两个界面各写一套。保存时固定本次所选价格和规则快照，历史不随共享资料更新。无报价的零件可显式选择共同价格资料；有报价可引用原快照，重新选价须明确记录。

投料重按用料规格、密度与确认的出件分配计算；有实测净重优先采用，并按投料金额减废料回收金额。无净重时引用报价重量及利用率，沿用现有报价“估算净重=投料重×利用率”的口径计算相同公式，标明估算来源；不把估算写成实测净重。缺报价重量/利用率时提示待完善，不以 100% 或零代替。旧版“直接采用报价成本总额”默认路径被本轮规则替代。

首版在价格中心提供“简易成本核算”，关联零件资料并展示来源、缺项和版本；历史客户价格查询与客户档案保留可达。后续“详细成本分析”入口、与简易核算的对照方式，以及“发货与应收准备”等界面待相应阶段细化，不展示成已可用功能。旧文档“基础/综合”分别对应简易核算/详细分析方向。

### 核算对象范围（用户已确认）

本次核算面向量产模具生产的零件方案，只接受**连续模或工程模**。按实际选定模具判断，不以零件已量产、报价已定点或 is_continuous=false 单独判定。非连续模还包含简易模等其他类型，必须明确分类为工程模才可纳入。

范围外方案不进入新核算；类型未知、字段矛盾或表格与主档类型冲突时列为待核对，先通过既有主档维护流程确认。导入不能自动将简易模改成连续模/工程模。连续模与工程模都可在基础、综合模式下核算，两种分类与两种成本范围互相独立。

该规则在 A 的候选、Excel 预览及 B/C/F 的新增/重算中统一执行。历史版本保持原类型快照；现有价格查询和实际发货保留各自数据范围，不因核算筛选遗漏数量。

### 首个可测试版本（A＋B）

1. 建立“京西重工成本核算”任务，保留资料截至日期、操作者和备注。
2. 批量加入关联零件，仅选确认属于连续模或工程模的量产方案；Excel 仅作为匹配与补充来源，预览后选择，重试不得重复加入。范围外及待核对行保留处理原因，不要求 20 行全部强行核算。
3. 每行明确客户别名、零件、模具和规格；并排展示系统值与表格值，冲突交由用户选择。
4. 展示毛重、净重、密度、出件/材料分配依据。已有重量先确认单位与含义；理论投料重可计算，覆盖时必须留原因。
5. 选择报价快照或共用材料价格及收费资料，记录采用的版本；有净重优先实际值，无净重按报价重量和利用率推算。来源或必要输入缺失逐项提示。
6. 在核算页补充表面处理并保存到 parts，关联同一套收费规则；即使材料价缺失也可先保存要求。特殊成本和模摊独立选用，均可不选，选用后说明金额/分摊依据，显示未选用、不适用、已知零、未知状态。
7. 试算简易成本，合计材料、表面处理及选用的特殊成本和模摊；有同口径参考售价时对比“售价与简易成本差额”。仅对选用范围内缺项提示，未选模摊/特殊成本及未启用详细分析资料不阻止完成。
8. 保存版本、重开、复制为新版本重算，导出当前版本明细、缺项和来源；源资料变化只提示，不改写保存结果。

Excel 预览与自动匹配不直接批量覆盖零件、模具或报价主档。用户在核算页实际补充并保存的表面处理要求是明确的主数据编辑操作，直接写回 parts；其他补充值仍按各自范围保留，不借此写回未编辑字段。导入候选要求可带入编辑区，用户保存后采用同一处理资料维护服务。

## 数据关联与来源规划

### 表面处理统一归属 parts（用户确认）

在 `parts` 新增结构化 `surface_treatment` 作为当前处理要求的唯一来源，零件页面和核算页面均可补充、修改并保存到这份资料；报价、生产及成本核算通过 part_id 和处理项标识引用。可记录多项处理方式、技术要求及图纸依据，明确待确认/无需处理/需要处理。该基础资料维护适用于零件档案，成本核算资格仍按连续模/工程模规则判断。

渐进补全流程：核算查询零件 → 带出现有处理项或待补充状态 → 填写已查明的处理及依据 → 保存处理资料 → parts 与审计记录一次事务写入 → 返回最新处理项和版本 → 当前核算草稿采用返回值，后续任务直接带出。此保存无需等待整份成本核算完成，也不再要求去零件页面重复提交。主档已保存而成本草稿尚未保存时分别显示两者状态；取消未保存的核算不会撤销已经明确保存的零件资料。

两处编辑复用同一后端字段校验、权限、并发版本和变更服务；记录本次核算任务/明细来源。保存只包含用户实际修改的处理资料，新增项使用稳定标识；清空/删除已有项必须是明确编辑操作。并发冲突展示当前值与本次修改，保留未提交内容供核对，不能自动覆盖。修改技术要求后当前未保存费用需重新核对，已保存核算/报价历史仍保留原快照。

费用在报价/成本中按具体处理项关联单价、单位、金额和来源；历史技术要求只保存当时快照。零件变更触发差异提示，不静默刷新已保存版本。已有 `prices.surface_treatment`、`quotes.treatment_items` 等先分清技术要求与费用：当前技术要求迁入 parts，金额及历史计价依据保留于原业务记录，不将混合 JSON 整包直接搬运。

`spray_status`、`spray_stamped_at` 列入兼容迁移盘点：确认实际业务含义，有效执行状态归入生产处理记录；默认 pending 不生成任何已确认处理要求。旧字段移除前必须执行 API 使用扫描和迁移验证，不在本轮规划中直接删除。

| 表格资料 | 现有来源 | 取数及处理原则 |
| --- | --- | --- |
| 原图产品编号、名称 | `part_customer_aliases`、`customers` | 按客户与有效别名匹配；待复核别名不能自动认定 |
| 本厂名称、材质、重量、图片、备注 | `parts` | 引用稳定 part_id；图片读取现有受控附件；重量须注明单位和含义 |

| 模具类型、工序数、穴数 | `tooling`、`tooling_steps` | 区分工序数、模具套数、穴数；表中“模数”不直接对应某个系统字段 |
| 表面处理要求 | 拟增 `parts.surface_treatment` | 当前要求统一从零件读取；其他模块引用处理项并保留历史快照 |

| 材料、废料单价及材料成本 | 共用价格资料、`quotes`、`prices`、`quote_groups` | 报价和核算共用取数/规则；明确本次选价或历史快照，现价不自动覆盖历史 |
| 表面处理费用 | 报价费用、旧台账、补充资料 | 关联 parts 中对应处理项，明确计价来源；技术要求不在各模块重复维护，修改同项只计一次 |
| 年度销售价格、数量 | `price_years` 及原始辅助表 | 历史参考，不能推断具体有效日期；统计期间未知时保留未知 |
| 期间实际销量 | `shipping_shipment_lines` → 订单行、发货确认记录 | 按实际发货日期、客户及零件汇总，不能按模具方案复制销量 |

**实际发现（2026-10-29 只读核对）**：京西存在材质、模具及多个规格记录；`18130664` 对应 `TYAN-Q0034`、`-P2`、`-P3` 及不同规格。所查京西零件重量字段为空；`prices`、有效未删除 `quotes` 关联记录计数均为 0。该检查限定本次连接和查询范围，不推断其他外部资料不存在。`18118285` 等 Excel 件号与系统别名存在后缀差异。

来源优先级不是“取最新一条”：先选正确身份与方案，再明确引用来源。多候选、字段冲突和缺项均返回具体原因。更换方案或报价后必须重新确认受影响输入并计算新版本。

| R9 | 特殊成本与模摊分别可选已确认；模摊金额来源/分摊量维护方式待细化 | 独立可选字段和依据，未选不阻挡首版；不默认按寿命或年销量分摊 | 模摊自动计算，不阻挡未选用的核算 |
| R4 | 工序工时及费率维护权限，多人、一人多机和设备占用时间 | 支持有来源的参考输入；特殊分摊未确认不自动计算 | C 的特殊场景 |
| R5 | 维护与资金占用的对象、期间及分摊量；电价、运行范围 | 已确认的金额与分摊数量可显式录入；不推断利率、折旧年限 | C 的自动分摊与 F |
| R6 | 售价有效期边界、合同计价时点、审批权限及兼容旧调价 | 自然日含起止日、缺价不延用仅为设计建议；实施前确认 | D 正式启用、E |
| R7 | 币种、含税、金额精度及舍入；销量来源和统计期间 | 内部 Decimal；建议单件 6 位、明细金额 2 位，待业务确认；历史 1—9 月与全年分开 | D/E 的正式金额，B 对比口径未齐时仅算成本 |
| R8 | 二维码净工时、人工投入、维修归属、有效产出与更正 | 先保留来源和分类；分摊细则另行确定 | F 自动取数 |

这些是分期门槛，不作为“全部业务规则已解决”的声明。当前无法给出全部阶段可直接实施的通过结论。

## Technical Context

- 前端：沿用 Vue 3、TypeScript、Element Plus、Pinia、Vite；不引入另一套页面框架。
- 后端：沿用 Python 3.11+、FastAPI、Pydantic、SQLAlchemy async、asyncpg、PostgreSQL；增量 Alembic 迁移。
- 计算：后端 Decimal 为唯一正式计算来源；前端展示与校验，保存和导出都读取版本结果。
- API：真实契约源为 `shared/api/registry.js`，经 `frontend/src/api/registry.ts` 导出；域模块调用 `api/client.ts` 与唯一底层 `utils/request.ts`。路径相对 `/api/v1`，声明 key、method、path、auth、lifecycle、description。
- 测试：pytest、数据库集成测试、现有类型检查/build、API 使用扫描、实际浏览器验收。文档本轮不执行功能测试。
- 规模：首个验收集 20 行，接口分页最大建议 100、导入先做文件体积/行数上限和超限提示；批量计算/导出阈值在实现前按实测定值。
- 性能验收目标（拟定）：同环境 20 行关联查询和试算各不超过 2 秒，导出不超过 5 秒；记录环境、缓存、样本、实际耗时；不把此目标当作已测结果。
- 权限：后端逐对象校验客户及记录访问、写入、导入导出和调价确认；先盘点现有授权，避免因最低角色等级相同而扩大成本可见范围。
