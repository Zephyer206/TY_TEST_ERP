# 机台生产浏览器验收

日期：2026-10-26（Asia/Hong_Kong）。范围：T027/T028；实现与自动化验收另见[本批报告](./phase4-production-acceptance.md)。全部数据为专用PostgreSQL合成夹具，页面为实际Vue入口、router、API client和后端认证路由，没有mock页面或业务库写入。

## 会话与身份

第一段使用Chrome扩展浏览器3、tab 1952681252，URL `http://127.0.0.1:18125/product-box-production`。随后浏览器及专用服务中断；用原始创建名称/OID核对并只读保存[第一段数据库结果](./phase4-production-first-db.json)，清理该自有库后启动新库继续验收。第二段使用可控的应用内Chromium浏览器2、tab 2，同一页面URL。用户未指定浏览器，因此按本项目本地UI验收规则选择会话，未做Chrome专属Windows身份匹配，也不声称做过该匹配。

合成JWT只保留在内存，使用101生产操作工、102生产主管、104订单401业务负责人和105另一订单负责人。页面顶部旧用户store仍显示“管理员”，不能据此认定当前请求身份；请求使用合成JWT，服务端允许动作和数据库operator_id/bound_by/completed_by/assigned_by为权限与操作身份依据。没有更改真实账号或正常服务认证设置。

## 按操作验证

| 阶段 | 实际操作与观察 | 结果 |
|---|---|---|
| 明确选单 | 101扫601机台；显示候选订单，进入前不自动创建产出；显式选401/产品301/CUT/路线v1 | PASS |
| 一次绑定 | 101扫描预发行unused标签1，点击绑定到当前订单；绑定人为101，初始0件 | PASS |
| 数量覆盖 | 同一框先保存30，再保存25；汇总及表格为25，默认订单25/备货0，未累加为55 | PASS |
| 多机/多单 | 再扫602并明确选402/产品302/CUT；两个机台选单按钮同时保留；切回601仍为401及25件，602为402及0件 | PASS |
| 错单框 | 402状态扫描401框，提示“该框与当前订单产品或路线版本不一致”；不出现该框数量写入入口 | PASS |

| 明确差异与取消 | 未勾选差异时最终确认禁用；取消后仍生产中；重新打开、勾选并确认后601已完成 | PASS |
| 完成范围 | 工人普通数量/完成入口关闭；602仍待生产，未关闭另一机台/订单 | PASS |
| 主管更正 | 新库重建101绑定→25→重扫完成；102选已完成401，普通登记不可用；更正25→20，填写“隔离验收实物复核”后成功 | PASS |
| 主管分配 | 102将有效产出20分为订单15/备货5；页面两列显示15/5 | PASS |

| 其他订单负责人 | 105扫601，提示该机台没有当前账号可用订单，进入订单禁用 | PASS |

浏览器多单场景为两台机对应两张订单；同一机台多个候选订单、票据过期/跨用户、stale版本409、并发分配、80→70+10及保留下游事实更正由真实PostgreSQL服务/API测试验证，不能把这些自动化结果称为已操作过的浏览器场景。浏览器通过不代表纸质扫码器或打印设备通过。

## 页面与修复

订单、产品/客户件号、机台工艺、已保存数量、目标及差异处于主要层级；框号标注辅助，原始标签身份折叠。路线显示实际revision，数据库route_revision_id不充当业务版本号。机台上下文只存本页内存，刷新或热更新后要求重扫。

实际浏览器发现当前ElementPlus版本的InputNumber忙碌切换后保留旧aria-disabled，导致可见控件和辅助功能状态不一致。按busy切换重建数值控件后，native disabled=false、aria-disabled=false，并通过实际输入/保存25、更正20和分配15/10复验。
