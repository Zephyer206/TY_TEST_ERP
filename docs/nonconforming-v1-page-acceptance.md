## 实现结果

- 不良品主菜单 → 不良品处理、返工模，路由分别为 `/nonconforming`、`/tooling/rework`。
- 零件主菜单 → 零件台账、模具台账。模具详情和维修页面也归属零件。
- 已移除售后档案与模具两个独立主菜单，不良品处理从仓储与后处理中移出。
- 不良品页面包含台账筛选、每周处理计划、排序与确认、详情和处理历史。
- 品质新增后进入待确认；确认处置方式、要求、负责人和计划完成日期后锁定内容与顺序。
- 返工、挑选、报废、其他处置共用待确认 → 待处理 → 处理中 → 待验收 → 已关闭。
- 含返工步骤的方案只记录模具是否就绪；第一步为挑选时可先开工，执行返工步骤前须由开发标记模具就绪。其他步骤不要求返工模。
- 品质、开发、业务可填写原因将未关闭的已确认记录退回待确认。任务暂停，保留原确认快照、已经验收数量和模具就绪情况。
- 品质可分次验收结果；全部数量都有结果后才关闭整条记录，并填写实际完成日期。验收不通过回到处理中，数量不重复累计。
- 按整条记录的计划完成日期归入任务周，不拆分成多个周数量任务。
- 返工模保存零件号、位置、可用状态、照片及关联不良记录。返工结果从关联记录读取。
- 沿用项目 Vue、Element Plus、现有设计变量与公司上下文，未新增业务 HTTP 调用。

## 按不良品明细表补充的页面能力

本轮只完善页面，未将 Excel 导入正式台账，未改动源文件、数据库或库存。原有预览记录通过新增默认字段兼容读取，不清空已有记录、已验收数量、模具就绪状态、计划或历史。

1. 单条记录支持顺序处理步骤，如挑选 → 返工 → 后处理。每一步保留执行人、完成时间和实际处理说明；步骤不累计验收数量。本轮全部步骤完成后才能提交实际完成数量。主流程仍是待确认 → 待处理 → 处理中 → 待验收 → 已关闭，周计划仍按整条安排。
2. 实际不良数量与预计后续退货分开。新增产品状态、字码、单件/成品、生产/退货批次、关联记录号、隔离位置、箱号和数量来源说明。同一条记录只对应同一种零件及产品形态，单件和成品分条登记后用记录号关联。可选数量分项合计必须等于本条实际数量；预测数量不参与合计。
3. 确认方案时须明确验收项目与标准。品质填写每个项目的处理后实测/核实结果及判定，核对本次实物数量。缺项、不通过或未核对数量时不能验收通过。不用异常描述中的数字自动判断是否合格。
4. 新增放行方式、批准人/单位、放行依据、处理后对应零件号、发货去向、标识、包装及批次/余料要求。让步放行确认前须填写批准依据及批准人；有放行/发货要求时品质须核对。对应零件号只记录本次处置关系，不修改零件主档。

部分验收后只累计本次通过的数量，剩余数量按同一方案进入下一轮，步骤重新记录。验收不通过不累计数量，也重新记录步骤。变更处理方案、计划或顺序仍须填写原因退回待确认；重新确认保留既有验收数量和模具就绪状态。已关闭记录不可从该入口退回。

每次验收快照保留当时的提交数量、已完成步骤、逐项实测及判定、数量核对、放行核对和当时的发货要求，后续修改不会覆盖原快照。返工模支持关联同件号且当前或历史方案包含返工的记录，避免剩余产品改为报废后丢失返工追溯。
