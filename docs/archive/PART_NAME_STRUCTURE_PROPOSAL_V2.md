# 零件名称数据结构方案（修订版）

## 核心理解

- **一级分类（必填）**：零件主名称，如"弹簧片"、"报警器"
- **客户零件名称（可选）**：客户定制的名称，如"摩擦片保持"、"摩擦片保持(右)"
- **备注（可选）**：其他说明信息

## 数据结构

### 简化的两层结构

```
一级分类（零件主名称）- 必填
  └─ 客户零件名称 - 可选
      └─ 备注 - 可选
```

### 具体示例

```
弹簧片 (一级分类)
├─ 摩擦片保持 (客户零件名称)
│  └─ 用于A车型 (备注)
├─ 摩擦片保持(右) (客户零件名称)
│  └─ 右侧安装 (备注)
└─ (标准件，无客户名称)
   └─ 通用型号 (备注)

报警器 (一级分类)
├─ XX客户定制型号 (客户零件名称)
│  └─ 带LED灯 (备注)
└─ (标准件，无客户名称)
   └─ 标准蜂鸣器 (备注)
```

### 选择行为

**场景1：标准零件（无客户定制）**
- 左侧选择：弹簧片
- 右侧选择：标准件（或显示为"通用型号"）
- 结果：只记录一级分类，customer_part_name 为空

**场景2：客户定制零件**
- 左侧选择：弹簧片
- 右侧选择：摩擦片保持
- 结果：记录一级分类 + 客户名称

### 新增逻辑

1. **只填一级分类**
   - 一级分类：弹簧片
   - 客户零件名称：留空
   - 备注：通用型号
   - → 创建标准件记录

2. **填写一级分类 + 客户名称**
   - 一级分类：弹簧片
   - 客户零件名称：摩擦片保持
   - 备注：用于A车型
   - → 创建客户定制件记录

3. **新建一级分类**
   - 点击"+ 新建一级分类"
   - 弹出输入框，输入新分类名
   - 然后可以继续填写客户名称

## 级联选择器数据构建

### buildPartNameCascader() 逻辑

```javascript
const buildPartNameCascader = () => {
  // 按一级分类分组
  const categoryMap = new Map()

  partNames.value.forEach(part => {
    const category = part.primary_category
    
    if (!categoryMap.has(category)) {
      categoryMap.set(category, [])
    }
    
    // 添加客户零件名称到对应分类
    categoryMap.get(category).push({
      id: part.id,
      label: part.customer_part_name || '标准件',
      value: part.id,
      remark: part.remark
    })
  })

  // 转换为级联选择器格式
  partNameCascaderOptions.value = Array.from(categoryMap.entries()).map(([category, items]) => ({
    label: category,        // 左侧：弹簧片、报警器
    value: category,
    children: items         // 右侧：摩擦片保持、标准件
  }))
}
```

## 唯一性约束

### 复合唯一索引
```sql
UNIQUE (primary_category, customer_part_name)
```

- 同一个一级分类下，不能有重复的客户名称
- 但可以有多个"标准件"（customer_part_name 为 NULL）

### 处理方式
为了允许同一分类下有多个标准件记录，可以：
1. 不设置唯一约束，在应用层控制
2. 或者在备注中区分不同的标准件
