# 零件名称数据结构方案演示

## 方案：四层结构

```
零件名称体系
│
├─ 一级分类（主分类/零件主名称）
│  ├─ 二级分类（子分类/具体零件类型）
│  │  ├─ 三级分类（客户零件名称）
│  │  └─ 备注
│  └─ ...
└─ ...
```

## 具体示例

### 示例1：弹簧片系列

```
弹簧片 (一级分类 - 零件主名称)
│
├─ 摩擦片保持 (二级分类 - 具体零件)
│  ├─ 客户A的定制件编号 (三级分类 - 客户零件名称)
│  └─ 用于XX车型，特殊工艺要求 (备注)
│
├─ 摩擦片保持(右) (二级分类 - 具体零件)
│  ├─ 客户B的零件号 (三级分类 - 客户零件名称)
│  └─ 右侧安装位置 (备注)
│
└─ 标准弹簧片 (二级分类 - 具体零件)
   ├─ (三级分类 - 可选)
   └─ 通用型号 (备注)
```

### 示例2：报警器系列

```
报警器 (一级分类 - 零件主名称)
│
├─ 声光报警器 (二级分类 - 具体零件)
│  ├─ 客户C指定型号 (三级分类 - 客户零件名称)
│  └─ 带LED灯 (备注)
│
└─ 蜂鸣报警器 (二级分类 - 具体零件)
   ├─ (三级分类 - 可选)
   └─ 标准蜂鸣器 (备注)
```

## 数据表结构建议

### part_name_dict 表字段

| 字段名 | 类型 | 说明 | 示例 |
|--------|------|------|------|
| id | Integer | 主键 | 1 |
| primary_category | String(100) | 一级分类（零件主名称） | "弹簧片" |
| secondary_category | String(100) | 二级分类（具体零件类型） | "摩擦片保持" |
| customer_part_name | String(200) | 三级分类（客户零件名称） | "客户A-FP-2024-001" |
| remark | Text | 备注 | "用于XX车型" |
| is_active | Boolean | 是否启用 | true |
| sort_order | Integer | 排序 | 0 |

## 使用场景

### 场景1：标准零件（只用一级+二级）
- 一级分类：弹簧片
- 二级分类：标准弹簧片
- 三级分类：留空
- 备注：通用型号

### 场景2：客户定制零件（用全部三级）
- 一级分类：弹簧片
- 二级分类：摩擦片保持
- 三级分类：客户A-FP-2024-001
- 备注：用于XX车型，特殊工艺要求

### 场景3：新增一级分类
- 先新建一级分类"密封件"
- 再添加二级分类"橡胶密封圈"
- 可选添加客户零件名称

## 级联选择器行为

1. **三级级联**：一级 → 二级 → 三级（可选）
2. **必选项**：至少选择到二级
3. **客户名称**：三级可选，如果没有客户定制需求可不选
4. **搜索**：支持全文搜索，可以直接输入"摩擦片"快速定位
5. **显示内容**：
   - 一级：只显示主分类名（弹簧片）
   - 二级：显示具体类型（摩擦片保持）
   - 三级：显示客户名称（客户A-FP-001）

## 问题和确认

1. **三级分类是否必填？**
   - 建议：可选。标准件不需要填写，定制件才填写

2. **同一个二级分类下可以有多个三级分类？**
   - 是的。例如"摩擦片保持"可以有多个不同客户的定制版本

3. **备注字段在哪里显示？**
   - 在级联选择器选中后，可以在表单下方显示备注信息
   - 或者鼠标悬停时显示tooltip

4. **一级分类是否支持动态新增？**
   - 是的。在快捷新增对话框中可以新建一级分类

5. **现有数据如何迁移？**
   - 弹簧片-摩擦片保持 → 一级:弹簧片, 二级:摩擦片保持
   - 报警器 → 一级:报警器, 二级:标准报警器（或其他合适的名称）
