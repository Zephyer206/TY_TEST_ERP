# Claude Code 前端数据查询与验收任务

## 模型与完成规则

- 默认模型必须使用 `claude-sonnet-5`。
- 只有同一个明确问题连续多次失败时，才改用 `claude-fable-5` 处理该问题；修复后继续按默认模型工作。
- 必须真实实现、启动前后端，并使用已配置的浏览器 MCP 操作网页验收。只跑单元测试、只调用 API、只看代码或只写报告都不算完成。
- 浏览器验收必须检查页面、网络请求、响应内容和浏览器控制台，并用只读 SQL 抽样对照数据库。
- 不得修改、清空或重新导入正式数据库；本任务数据库只读。
- 不得创建或伪造价格数据。当前价格数据尚未导入，前端应明确显示“暂无价格”和“暂无调价记录”。
- 工作树已有大量用户和其他智能体改动，不得回退、覆盖无关改动，不提交 Git。

## 必读资料

开始前完整阅读：

1. `CLAUDE.md`
2. `specs/001-erp-system-architecture/data-model.md`（唯一权威数据设计）
3. 当前相关 ORM、API、前端路由和页面

禁止继续以这些旧字段作为正式关系来源：

- `parts.customer_id`
- `parts.customer_product_no`
- `parts.mold_number`
- `tooling.customer_id`
- 通过 `quotes` 推断客户的全部零件

正式关系必须来自：

- 零件—客户：`part_customer_aliases`
- 零件—模具：`tooling_parts`
- 模具—客户：`tooling_customer_links`
- 模具步骤：`tooling_steps`
- 零件客户价格：权威设计中的 `price_accounts` 语义；先核对实际数据库/ORM的兼容表名与字段，不得臆测或迁移数据
- 调价历史：`price_adjustments`，按实际数据库现状只读查询，并在报告中说明与权威设计是否仍有差异

## 功能一：零件参数与关联关系查询

完善零件列表和详情，使用户可以从前端搜索真实零件并查看：

- 数据库内部 ID（当前没有内部零件业务编号，不能把客户件号冒充内部编号）
- 内部零件名称 `parts.internal_name`
- 材料
- T / W / P
- 毛重、净重
- 位置、状态
- 所有关联客户，而不是单一客户：客户名称、客户代号、客户件号、客户件名、车型、版本、是否有效
- 所有关联模具，而不是文本模具号：模具号、模具名称、模具类型、是否连续模、穴数、非连续模步骤数、状态
- 非连续模的 `tooling_steps` 明细（步号、代码、名称、工序、顺序）；连续模不得伪造步骤
- 必要时显示模具关联客户，清楚区分“零件客户别名关系”和“模具客户关系”

API 必须批量查询或合理预加载，避免明显 N+1。搜索应至少支持内部零件名称、客户件号、模具号，并按关系表实现。

## 功能二：指定客户全部零件价格与价格历史

完善客户价格查询页面：

- 可以搜索并选择任意真实客户（显示客户名称和客户代号）。
- 客户的零件集合必须从 `part_customer_aliases` 获取，不能从 `parts.customer_id` 或 `quotes` 推断。
- 即使没有价格账户，也必须通过左连接保留该客户的全部关联零件。
- 每行显示内部零件 ID、内部名称、客户件号、客户件名、材料、当前价/基础价等实际存在的价格字段。
- 没有价格账户或价格字段为空时明确显示“暂无价格”，不得显示 0 元或提供会误写正式数据的快捷造数按钮。
- 可以查看每个客户—零件组合的调价历史；没有记录时明确显示“暂无调价记录”。
- 价格与调价字段必须基于实际数据库和权威设计核对。若当前数据库仍使用兼容旧表名或旧字段，先做只读兼容查询，不得在本任务迁移或写数据，并在报告列出差异。

## 浏览器 MCP 强制验收

实现后必须用 Claude Code 已配置的浏览器 MCP 做以下真实操作，并保存截图到 `screenshots/frontend-data-verification/`：

1. 登录系统，记录实际前端 URL 和测试账号角色（报告中不得记录密码）。
2. 打开零件页面，确认无页面级报错、无乱码、无明显布局错误。
3. 从数据库先用只读 SQL 选择至少 3 个具有不同关系特征的真实零件：
   - 至少一个有关联客户和模具；
   - 尽量包含一个多客户或多模具零件；
   - 至少一个非连续模且有步骤明细的零件。
4. 在前端分别用内部名称、客户件号、模具号搜索这 3 个零件，打开详情；逐字段与 SQL 查询结果对照。
5. 检查每次相关网络请求：HTTP 状态必须成功、请求参数正确、响应不依赖废弃关系字段。
6. 选择至少 2 个真实客户（优先选择关联零件较多、且彼此数据特征不同的客户），验证页面列出的零件数量和抽样内容与 SQL 一致。
7. 验证价格未导入时仍能看到全部关联零件，页面显示“暂无价格”；打开历史后显示“暂无调价记录”。不得为验收写入价格。
8. 检查浏览器控制台；与本功能有关的 error、未处理异常、404/422/500 必须修复后重新验收。
9. 截图至少包括：零件列表搜索、零件详情客户关系、模具与步骤、两个客户的价格列表、暂无价格/暂无历史状态、网络请求检查结果。

如果浏览器 MCP 不可用，任务状态必须标记为“未完成”，继续排查 MCP 配置；不能改用“仅 API 测试”宣称完成。
