# 研发项目全流程讨论稿

整理日期：2026 年 10 月 14 日。最近更新：2026 年 10 月 15 日。版本：讨论稿 v0.11。

用途：在现有 ERP 业务流程上细化新项目开发、研发记录、费用归集和备查。当前交付为业务讨论文档，未修改代码、数据库或正式 spec。本稿中的建议方案和待讨论项，后续讨论确认后再写入正式规格。

## 1. 已确认的业务规则

| 编号 | 已确认内容 |
|---|---|
| C01 | 一个项目包含一个或多个零件，以项目为统一跟进单位。 |
| C02 | 业务经理接手报价，收到客户定点函后业务项目正式开始。 |
| C03 | 定点函可能覆盖多个零件，也可能分批收到；后续零件可以关联已有项目。 |
| C04 | 业务经理和项目组目前不作职责流程拆分，统称项目负责人员；开发目标直接在项目内填写。 |
| C05 | 研发立项最终由老板批准。 |
| C06 | 研发内容从两条主线记录：产品帮助客户改善什么；产品开发遇到什么技术问题、怎样解决。 |
| C07 | 立项填写预估预算，项目完成后统计最终费用。原始业务和投入记录随实际发生积累。 |
| C08 | 开发任务包括计划任务，以及会议、试制、检测或客户反馈产生的问题处理任务。 |
| C09 | 线上会议提供会议截图；线下会议提供签字材料及现场照片。会议同时保留讨论事项、结论和后续任务。 |
| C10 | 本人完成个人工作后填写实际工作内容和工时；统一会议登记实际参会人员，统一填写时间，由系统形成参会人员工时。 |
| C11 | 讨论顺序为新项目开发、老项目改进、历史项目记录补全；当前重点为新项目。 |
| C12 | 目前试模没有设备使用时间记录，新流程应简化现场操作，支持纸质填写。 |
| C13 | 试模记录落实到实际试模人员本人：本人直接填写系统，或本人填写纸质卡后由其他人员录入。实际试模人与代录人分别记录。 |
| C14 | 项目发出打样或开模需求，由开发内部安排执行人员及计划时间。 |
| C15 | 本人只填写实际开始时间和实际结束时间，由系统自动计算时长，不另手填实际用时。纸质卡采用同样的起止时间口径，代录后由系统计算；开发计划时间单独保留。 |
| C16 | 谁工作谁记录，本人提交确认；正常记录进入项目台账，异常记录再处理。开发管理任务、进度及定期或异常核查，日常工时不增加逐条审批。纸卡代录保留本人原始依据。 |
| C17 | 记录支持按人员、项目或期间汇总导出为可打印文档，集中供本人签名并留存。具体表单范围、导出格式及打印签字频率待细化。 |
| C18 | 现场既有专门试模设备，也使用正常生产共用设备，两类设备均纳入流程考虑。 |
| C19 | 目前正常生产报工仅记录数量，未记录设备实际开始、结束时间。共用设备记录责任已明确，生产时间登记入口和与原报工的衔接待细化。 |
| C20 | 共用设备的使用由当次实际操作人员记录；试模有专人负责，由实际负责操作的试模人员填写或本人填写纸卡后代录。 |
| C21 | 目前找仓库进行的这项登记记录材料需求数量，未包含实际发料数量；其他出库单据及退料流程尚待确认。 |

线上截图、线下签字和照片，是本项目已确认的内部归档方式，不表述为税务总局规定的统一会议材料格式。

以下各章在已确认规则上补齐建议方案；登记时点、确认人、分摊方法、变更审批等细节尚待讨论。

## 2. 政策依据和管理边界

业务项目覆盖客户开发和交付。研发记录应识别其中的研发活动、人员及投入范围。客户定点、老板批准、上传照片本身不构成税务或高新认定资格判断的全部依据。

研发加计扣除关注创造性应用或实质性技术改进等活动，常规升级、简单改变、日常质量控制及维修维护等活动不适用。拟纳入研发的工作应有技术目标、研究或验证过程及依据。[税务总局研发活动说明](https://www.chinatax.gov.cn/chinatax/c102419/c5204648/content.html)

高新认定材料包括立项、成果转化、研发组织管理及研发活动说明等资料。因此，平时记录应能支持说明技术内容、过程和成果。[高新技术企业认定管理办法](https://www.most.gov.cn/xxgk/xinxifenlei/fdzdgknr/fgzc/gfxwj/gfxwj2016/201602/t20160205_123998.html)

加计扣除备查材料包括研发计划书、内部立项决议、项目组及人员名单、适用的研发合同、费用分配依据、辅助账及汇总表等。可以整理复用日常已有资料；下文的简短登记内容需与附件共同形成所需资料。[税务总局留存资料说明](https://www.chinatax.gov.cn/chinatax/n810351/n810906/c5169537/content.html)

会计、高新认定、研发加计扣除存在归集口径差异。管理上保留同源数据、各口径结果及调整理由，不强求金额相同。[2026 年税务部门口径说明](https://qingdao.chinatax.gov.cn/hdjl2019/zxft/wqhg/202605/t20260519_104522.html)

老板是内部研发立项批准人。税务优惠适用及申报由企业结合实际情况和政策核定；内部批准不代替该判断。

## 3. 新项目总体流程

报价及技术评审 → 收到定点函 → 建立或关联项目 → 确认零件及开发范围 → 项目填写目标、计划、人员和预估预算 → 老板批准研发立项 → 开发任务、会议及问题跟进 → 记录工时、设备、材料和外协 → 阶段验证 → 结项或终止 → 核定最终费用 → 项目及年度档案。

业务项目状态与研发立项状态分别保留。收到定点函后按真实业务启动；研发实际开始日期、内部批准日期分别登记。定点前发生的真实技术工作保留原时间和依据。

建议业务状态：已启动、开发中、暂停、已移交或结束。建议研发状态：待评估、待完善、待老板批准、已立项、执行中、已结项或已终止。状态名称和切换条件待确认。

## 4. 建立项目及研发立项

| 内容 | 建议安排 |
|---|---|
| 项目标识 | 内部编号、名称、客户及客户项目号。已有报价信息可带入，内部编号规则待确认。 |
| 零件范围 | 关联一个或多个零件、报价及图纸版本；新零件分批定点时追加关联。 |
| 定点依据 | 保存定点函，分别记录函件日期、实际收到日期及登记时间。 |
| 开发内容 | 填写两条主线中适用的目标和技术问题，关联客户要求、评审或图纸。 |
| 研发范围 | 明确哪些零件、任务属于拟研发范围；同一业务项目中的常规工作分别标记。 |
| 实施计划 | 主要设计、试制、测试任务，预计开始和完成日期，以及验证方法。 |
| 实际参与人 | 初始名单及职责，后续参与和退出变化留存。 |
| 预算 | 按项目整体预估，保留估算依据；共用投入避免按零件重复估算。 |
| 开展方式 | 根据实际业务及合同区分自主、委托、合作等形式；客户委托关系另核对。 |
| 批准记录 | 老板的决定、日期、意见及对应资料版本。 |

建议将研发技术内容收敛为“为什么做、准备怎样做、怎样验证”，已有评审文件可以引用。阶段性实际成果在开发过程中更新。

建议老板可以批准、退回完善或决定不纳入研发。研发范围、重要技术目标及预算重大变化是否重新批准、何为重大变化，列为待讨论项；普通进度记录在项目内维护。

待讨论：项目命名和编号、负责人是否默认报价经办人、立项所需最少附件、多个不同研发活动是否在同一业务项目下分别编号。

## 5. 开发任务、问题和技术变更

计划任务由开发目标产生；问题任务由会议、试制、测试或客户反馈产生。统一记录执行人员、涉及零件、计划时间、实际处理、验证结果及附件。

已确认的需求和安排流程：项目发出打样或开模需求，说明项目、零件范围、工作要求及需要的交付；开发内部安排实际执行人员和计划时间。需求内容与开发安排分别留存，实际执行记录关联对应需求和任务。具体需求字段及安排变更规则尚待细化。

建议流程：安排 → 执行 → 验证 → 确认完成；未达到目标时保留当次结果，并关联下一轮处理。暂停、取消或终止注明原因和剩余事项。

任务可以针对单个零件、多零件或项目共用工作。讨论、图纸、试验、人员和设备记录引用同一任务，减少重复叙述。

图纸或工艺变化保留修改前后版本、原因、涉及范围和验证依据。验证记录应能追到采用的方案和样品批次。技术内容发生变化时，原记录保留，追加或形成新版。

待讨论：需求和开发安排的最少内容、实际记录及任务结果由谁确认、客户验证与内部验证如何分别记录、变更什么时候更新研发计划。

## 6. 会议及会议工时

| 方式 | 已确认的证明材料 | 同时保留的内容 |
|---|---|---|
| 线上 | 会议截图 | 时间、实际参与人、项目及议题、结论、待办。 |
| 线下 | 签字材料及现场照片 | 时间、实际参与人、项目及议题、结论、待办。 |

签字材料可采用签到表或签字纪要，具体形式待确定。一次会议的附件保存一份，议题和待办分别关联对应项目、零件和任务。

统一填写会议时间后，为实际参会人员形成带会议来源的工时。中途加入、提前离开按实际参与时间调整。多人参加一小时会议，各人记录自己的投入，项目合计为人时；同一人的同一时段不重复记入个人工作。

会议涉及多个项目时，按实际议题时段合理分配。研发讨论与其他会议内容分别识别，参会名单不自动等同于可归集人工费用名单。

会议结论形成行动任务，验证结果再关联回讨论记录。实际发生的会议开支关联报销和凭证，由财务核定费用类别；人员会议工时进入人工记录。

待讨论：谁统一登记会议、参会时间更正由谁确认、跨项目议题时段怎样填写。

## 7. 个人工时和人工费用

已确认：个人工作由本人在完成当天或阶段工作后填写；会议工时统一登记。

建议记录人员、实际工作日期、项目及任务、简短工作内容、实际时长和已有工作依据。跨多日任务分实际发生日期记录，保留研发和非研发工作区分，并与考勤、报工等资料核对。

汇总流程按已确认原则细化为：个人填写并提交确认，会议工时按既定方式统一登记；正常记录进入项目台账，异常由本人更正或说明，必要时由开发核实，再按期间汇总供财务核算。日常个人工时不增加逐条审批，项目成员名单、人事身份资料和工时相互关联。

同一时段涉及多个项目，分配后不超过实际时间；试模人员工时与机器使用时间分别记录。项目人员维护工作和时间，工资等金额由财务维护。

共用研发、非研发人员的相关费用，应以活动记录支持按实际工时占比等合理方法分配。[第 40 号公告的人员规定](https://www.chinatax.gov.cn/chinatax/n810341/n810765/n2511651/201712/c3300345/content.html)

待讨论：打印签字频率、异常核查责任及更正规则、代录核对方式，外聘人员资料如何取得。具体频率属于企业管理安排。

## 8. 设备使用及折旧：本人记录及时间填报简化原则已确认，其余细节待讨论

目前试模没有设备使用时间记录。新流程由实际试模人员对原始记录负责，采用本人系统填写、本人纸质填写后他人代录两种方式。生产或其他检测是否已有可引用记录，另行核实。

| 已确认的填写方式 | 责任及来源 |
|---|---|
| 本人直接填写系统 | 记录实际试模人及本人提交信息。 |
| 本人填写纸质卡、其他人员录入 | 实际试模人是原始填报人；系统同时保留代录人及录入时间。 |

为减少现场填写，建议项目提出需求时带入项目、零件和技术要求，开发安排时补充执行人员、计划时间及适用的模具和设备信息，现场沿用这些资料。具体预置内容尚待确认；扫码和计时按钮属于可选便利方式。

本轮确认：实际执行只填写开始时间和结束时间，由系统自动计算时长，不要求本人再填写实际用时。开发内部安排的计划时间另行保留，与实际执行分别记录。

本人直接填写系统时，录入实际起止时间，系统计算“结束时间减开始时间”。本人填写纸质卡时，写明对应日期和起止时间，由代录人按原卡录入，系统完成同样的计算。跨日记录需能识别实际日期。

自动计算得到的是该次起止时段的原始时长。中断、等待、转正常生产等情况如何记录或扣除，以及哪些时段用于后续费用分配，另行讨论；当前不增加已确认之外的现场操作要求。

设备实际使用时间与个人实际投入分别统计，可能相同也可能不同。两类时间怎样最少填写、怎样核对，仍需讨论；设备时间不按参与人数累计。

纸质卡建议保留本人签名、填写日期和卡片编号，代录时关联原卡扫描件或照片。原业务发生时间与代录时间分别保存；更正保留原因和确认记录。签字形式、原卡保存和代录核对人仍待确认。

多人参加同次试模时，建议分别记录各人的实际投入，关联同一次设备使用记录。个人责任与个人工时分别落实，设备时段据实记录，不按参与人数重复累计。

本人提交确认后，正常记录进入台账，异常先由本人修正或说明，必要时由开发核实。代录内容与本人原卡对应，代录人不替代实际工作人。财务按月份核定金额和分摊，结项时汇总；异常核查人、频率及代录核对细节待确认。

已确认现场既有专门试模设备，也有与正常生产共用的设备。建议按以下方式衔接，具体分摊方法仍待讨论：

| 设备情况 | 建议记录和归集方式 |
|---|---|
| 专门试模设备 | 确认当期实际研发用途，试模记录关联项目；涉及多个项目时，按实际使用等合理依据分配。专用标签本身不直接确定归集比例。 |
| 生产、试模共用设备 | 同时取得研发和正常生产使用记录，再按合理依据分配；采用实际工时方法时，应能核对对应期间全部实际使用时间。 |

建议设备编号、类别及财务资产关系由开发和财务核实维护，开发安排任务时关联设备，现场人员确认实际使用设备并填写起止时间。设备归类和折旧金额不增加为现场试模人员的填写事项。

共用设备记录责任已确认落实到当次实际操作人员：正常生产由生产操作人记录，试模由当次负责操作的试模人员记录。用途、设备及对应任务应能区分生产与试模，具体信息带入和登记入口仍待细化。已有本人填报、纸卡代录、系统计算及打印签名规则沿用。

已确认正常生产报工仅记录数量，没有实际起止时间。若采用前述实际工时分摊方法，共用设备还需取得对应期间正常生产的实际使用时间，现有数量不能直接作为实际时间占比。

建议优先在参与试模的共用设备生产报工中，随原数量记录补充实际开始、结束时间，由系统计算时长；由实际操作人填报，保留系统填写或本人纸卡后代录的简化思路。操作人负责记录已确认，是否直接扩展生产报工入口尚待细化，不作为已批准的代码实施要求。

如果生产报工暂时不适合承载时间，可讨论先使用简易设备时间卡，按实际生产、试模及中断时段登记。具体是否按任务、批次或设备时段记录，以及一人操作多台设备如何区分，需结合现场情况确认。

来源不完整时标记待补充依据，不把全部试模时间当成设备全部使用时间，也不自动将计划班次或数量乘标准节拍的估算值作为实际使用时间。是否采用其他合理分摊方法，由财务结合真实可取得的记录另行评估。

采用实际工时方法的示例：某月核定折旧基数 6,000 元，设备实际总使用 100 小时，其中项目 A 20 小时，项目 A 分摊为 1,200 元。项目设备时间占比的分母包含对应期间全部实际使用时间，不能仅使用研发工时作为分母。

设备按实际使用时段计时，三人共同操作一台设备一小时，设备时间仍为一小时。设备同时处理多个项目时保留分配依据，不重复计算。

共用设备折旧需有使用记录和合理分摊依据；加速折旧的加计扣除采用税前扣除口径。[第 40 号公告的折旧规定](https://www.chinatax.gov.cn/chinatax/n810341/n810765/n2511651/201712/c3300345/content.html)

财务分别保留会计和税务折旧基数及差异。经营租赁、未折旧或无有效使用记录等情况单独核定，不直接套用比例公式；设备购置价与当期折旧分开处理。

待讨论：共用设备正常生产时间的采集方式和适用范围、一人多机及记录粒度、现场其他最少填写内容、跨日及分段记录、纸卡签字和原卡保存、异常核查责任、代录核对及更正规则、中断和等待时段的处理、设备与人员时间区分、分摊方法和闲置期间核定。试制与检测是否沿用同样的本人记录方式，另行确认。

## 9. 材料、试制与样品去向：部分已确认，其余待讨论

已确认现状：需要材料时找仓库登记需求数量，当前讨论的这项登记未包含实际发料数量。其他出库单据是否记录实发数量仍待了解。需求数量不直接当作已发料或实际消耗数量。

建议沿用仓库登记入口：项目打样或开模任务 → 仓库登记材料需求 → 记录实际发料 → 试制 → 退料或实际消耗确认 → 样品及废料去向 → 关联财务金额。新增关联内容和实际发料记录方式需继续讨论确认。

为减少重复填写，建议需求记录关联项目及具体任务，复用材料名称、规格和需求数量；在同一记录或关联的原出库单据中，由仓库发料时确认实际发料数量，少发、多发或分批发料时按实际记录。复用已有材料信息，不要求重新填一套申请表；需求数量不能未经确认直接作为实发数量。该发料方案尚未确认，具体登记人、单据形式和确认方式待讨论。

| 环节 | 最少要能追到的事实 |
|---|---|
| 材料需求 | 关联项目及任务、材料及规格、需求数量；与实际发料数量区分。 |
| 领料与退料 | 项目或任务、材料、批次、数量、原仓库单据。 |
| 共用材料 | 涉及的项目、实际分配数量及依据。 |
| 试制 | 样品批次、零件、采用的方案或图纸版本、数量和结果。 |
| 样品去向 | 客户送样、内部留样、试验消耗、报废、销售或转生产及依据。 |
| 废料及其他产出 | 处理数量、去向及相关收入单据。 |

金额和计价由仓库、财务按原业务资料核定，项目人员记录实际用途和数量。样品状态变化继续沿原批次追溯。

研发直接形成产品对外销售时，对应材料涉及加计扣除调整；下脚料等特殊收入也有相应处理，因此去向和收入需关联。[第 40 号公告的材料及收入规定](https://www.chinatax.gov.cn/chinatax/n810341/n810765/n2511651/201712/c3300345/content.html)

待讨论：是否存在另行记录实际发料数量的出库单据、需求与领料是否沿用同一记录及如何关联项目任务、仓库确认实发数量的方案、剩余材料退库或留在现场的现状及退料确认、免费送样和收费销售如何区分、共用材料计量依据。

## 10. 模具、外协、委外研发与采购：建议方案

模具准备和试模沿用原模具记录，关联项目、零件、修改及验证。共用模具保留涉及范围和投入分配依据。模具开发、固定资产折旧及其他处理由财务按事实核定，避免将同一投入重复归集。

采购和外协依原流程进行，增加项目及用途关联。保留采购或外协工作内容、合同、交付、验收、发票、付款及凭证间的关系。

需区分购买现成物资、普通加工、检测服务、委托研发、合作研发及我们承接客户研发委托。客户付费、定点函或模具费名称本身不替代合同和实际工作性质判断。

研发合同核对技术任务、交付、成果或知识产权归属、费用承担，及适用的技术合同登记资料。境内委托研发加计扣除按实际发生额的 80% 计入委托方研发费用，受托方不得重复享受；合作研发各方按自身实际承担费用处理。[税务总局委托、合作研发说明](https://www.chinatax.gov.cn/chinatax/n810356/n3010387/c5192627/content.html)

待讨论：常见外协工作有哪些、是否存在客户委托研发及开发费、谁确认合同性质和成果归属。境外、关联方等情况在实际涉及时另行细化。

## 11. 月度核对、年度核算和最终费用：建议方案

已确认：老板审批预估预算，项目完成后统计最终费用。

建议日常按实际发生积累记录，财务按期间处理账务、核对和保留辅助账，结项时再汇总全项目最终金额。跨年度项目同时保留各年度记录和累计费用，不等结项才归集前期事实。辅助账需按项目准确归集当年费用。[税务总局核算要求](https://www.chinatax.gov.cn/chinatax/c102419/c5204648/content.html)

建议每个期间核对：人员及会议工时、设备使用和金额、材料领退及样品去向、外协验收及凭证、共用投入分配、重复或遗漏、资本化与费用化处理及税会差异。

| 层次 | 结果 |
|---|---|
| 项目实际总投入 | 反映项目真实投入，包含核定后的相关实际费用。 |
| 会计核算 | 财务按适用会计制度和凭证处理费用及资本化。 |
| 高新认定口径 | 按高新工作指引核定研发费用。 |
| 加计扣除口径 | 按税务规则核定、调整并形成辅助账和汇总表。 |

其他相关费用的加计扣除限额按规定对全部研发项目统一计算，不能把每个项目简单各算一遍再汇总。[2021 年第 28 号公告](https://fgk.chinatax.gov.cn/zcfgk/c100012/c5194995/content.html)

实际费用与预算差异用于分析。更正保留原值、原因、时间和确认人。核对存在缺项时标记待核定，不把估算当作实际金额。

待讨论：月度核对由谁组织、财务资料来自现有账或导入、重要预算变化如何处理、缺项费用如何跟进，以及各口径差异清单的确认方式。

## 12. 阶段验证、成果与结项：建议方案

建议结项流程：整理各任务结果 → 核对目标与实际效果 → 汇总技术文件及客户验证 → 确认剩余事项及研发结束范围 → 财务汇总最终费用 → 内部确认结项 → 归档。

成果说明沿用两条主线：客户获得的实际改善；我们解决的技术问题及依据。记录未达成目标、失败尝试和原因，技术结果与客户验收分别保存。

建议关联最终图纸和工艺版本、样品批次、测试及对比数据、适用的知识产权、客户验证及产品或服务。业务项目完成或开始量产，与具体研发活动结束时间分别确认；后续新技术活动另记录范围。

失败或终止项目保留已开展活动、投入、原因、终止日期、内部决定及剩余材料或合同处理。符合规定的失败研发活动费用可加计扣除。[2025 年税务部门答复](https://tianjin.chinatax.gov.cn/11200000000/0300/030005/20250729105842728.shtml)

待讨论：最终结项是否也由老板确认、客户未验收时能否先完成内部研发阶段、量产后新增技术工作的归属、剩余事项如何关闭。

## 13. 高新收入、档案与查询：建议方案

研发项目或活动 → 技术成果及适用知识产权 → 产品或服务 → 收入明细及财务凭证。该关联用于后续高新资料整理；产品及收入是否纳入由实际技术支持关系和适用口径核定。

高新认定还涉及技术领域、知识产权、科技人员、研发投入和高新收入等条件。指标以正确期间和口径统计，不以预算或项目标签判断达标。[认定条件](https://www.most.gov.cn/xxgk/xinxifenlei/fdzdgknr/fgzc/gfxwj/gfxwj2016/201602/t20160205_123998.html)

建议项目档案包括业务来源及定点函、研发计划和批准记录、人员、任务、会议、技术版本及验证、工时、设备和材料、外协合同及验收、费用分配及凭证、结项或终止、成果关联。

同时按会计年度整理辅助账、汇总表、申报使用资料和口径调整。一次附件可以由多条记录引用，保留原件或原始电子文件的来源和版本，导出目录能定位到文件与单据。

税收优惠留存备查资料从享受优惠事项当年的企业所得税汇算清缴期结束次日起保留 10 年；财务等其他档案另按适用期限管理，兼顾更长期限。[2018 年第 23 号公告](https://tianjin.chinatax.gov.cn/11200000000/8000/800012/80001204/p20190314135602962.shtml)

建议查询维度：项目、客户、零件、任务、人员、设备、期间、费用类别、资料缺项。常用结果：项目进度及待办、投入及费用明细、预算差异、凭证追溯、档案目录和各口径差异。

已确认增加可打印文档导出，供本人签名留存。建议区分两条路径：

| 路径 | 建议流程 |
|---|---|
| 本人直接录入系统 | 本人填写并提交 → 按人员、项目或期间选择记录 → 导出打印 → 本人签名 → 纸件归档，签字件照片或扫描件关联回原记录。 |
| 本人填写纸质卡、他人代录 | 本人填写原卡并签名 → 代录人按原卡录入 → 保存原卡及电子附件 → 需要汇总时再导出；已有签字原卡优先复用，避免重复抄写。 |

打印模板建议覆盖试模工作记录、个人项目工时、设备使用及会议记录等适用资料；具体范围尚待确认。建议以适合打印的 PDF 为主要输出，纸卡可以预印已有任务信息；如需 Excel 核对另行讨论。

打印内容建议包含项目和任务、实际工作人、工作内容、设备、实际起止日期时间及计算时长，预留本人签名和实际签字日期。表单编号、打印批次、记录版本和页码用于关联纸件与系统记录，具体格式待确认。

建议支持按个人、项目或期间汇总多条记录后集中签名，签字频率尚待讨论。纸质签名确认的是所打印版本，后续更正保留原记录与原签字件，关联更正版及必要的重新签认，避免新旧版本混淆。电子回传件与纸质原件的保管位置分别登记。

待讨论：打印表单范围、格式和签字频率、谁组织打印及归档、签字件回传责任；谁可看工资和财务明细、资料更正及导出权限、现有知识产权和收入资料怎样关联、档案保存位置及备份方式。

## 14. 后续第二阶段：老项目改进，仅列讨论框架

原生产历史与本次改进分别追溯，本次归集只对应真实研发范围和期间。可在同一项目下进行多次改进，各次的目标、时间、投入和成果分别保留。

## 15. 后续第三阶段：历史项目记录补全，仅列讨论框架

先盘点现有报价、定点函、图纸、模具、试制、检测、会议、领料、人员及财务资料，再按来源关联回项目。补录保留业务实际发生日期、当前录入日期、原资料来源、补录人及确认记录。

区分有原始依据、需核实、无法证实三种情况。缺失资料进入待核实清单；未证实的工时、数量和金额保留缺项，不填成确定事实。补全的目标是还原实际活动及费用关系。

待讨论：优先整理哪些年度及项目、由谁提供资料、缺项如何核实、已有申报或核算差异如何交财务评估。
